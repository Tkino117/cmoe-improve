# 07 スパース率50%（N=8 / A=4）で、06 と同じ配分探索を回す

## 目的

[report/07](../../report/07_slimpajama-alloc-3seeds.md)（N=8 / A=6、スパース率
25%、seed 3本）はこうだった。

- **PPL**: 主役の幅4 で、3対照 × 2評価セットの6箇所すべてが判定を満たした
- **ベンチ**: `gold_nll` は固定 `uniform3` に対してのみ満たし、**校正で選んだ
  一様に対しては区間が0をまたいだ**（幅4 で −0.014 [−0.030, +0.002]、符号の
  一致も 1/3）

ベンチが決まらない理由は report/07 の「効き目の限界」に書いたとおりで、効果量が
`acc` で 0.005 程度・区間の半幅が ±0.005 と、**seed 3本では桁が足りない**。

ここは**動作点だけを厳しくする**。A=6 → A=4 で、1トークンあたりに走る expert が
8個中4個になり、捨てるぶんが 25% → 50% になる。層ごとに shared を何個置くかの
効き目もそのぶん大きくなるはずで、効果量が伸びればベンチでも見える。伸びなければ
「動作点を倍にしても、この設計のベンチでは見えない」が分かる。どちらでも次に
進める。

**言わないこと。** report/07（25%）との差そのものには統計判定を当てない。別の
実行・別の動作点で、対応の取れる単位（同じ問題・同じ塊の上の差）が無いからで
ある。25%の数字は**記述として並べる**だけにする。

## 固定するもの

A **以外は report/07 と1つも変えない**。

| | |
|---|---|
| モデル / 層数 | `meta-llama/Llama-2-7b-hf` / 32 |
| N / A | **8 / 4**（スパース率50%。x をどう振っても1トークンあたりに走る expert 数は同じ） |
| 校正 | slimpajama n=16 × 2048、seed 0 / 1 / 2 |
| 採点オラクル / 探索 | `suffix_kl` / beam 幅2・3・4 |
| 配分 | 一様 x=0〜4 と、探索の3幅 |
| ルーター / 分割 | 現行 CMoE（k_act 10 / bias_speed 0.001） |
| ベンチ | PIQA / WinoGrande / ARC-e / ARC-c / HellaSwag、0-shot 全件、batch 32 |
| PPL | wikitext2 / c4-new |
| ブートストラップ | 10,000回 / seed 20260813 |

**N は動かさない。** N を変えると expert 1個あたりのニューロン数（分割の粒度）
まで動いて、比べているものが「配分」でなくなる。A だけを動かせば、同じ分割・
同じ粒度で走らせる数だけが半分になる。

dense の基準は測らない。report/04 の
`result_logs/bench_h4/wikitext2_seed0/bench/dense.json` を取り込む（dense は
変換していないモデルなので、**A にも**校正にも seed にも配分にも依らない）。

## 走らせる前に決めたこと

走らせてから指標を選べば、18箇所の中の1つは必ず何か言う。だから先に書く。
判定の枠組みは report/07 と同じにする — **動作点を変えた効果を見る実験で、
読み方まで変えたら比べられない**。

- **主要評価は PPL**（wikitext2 / c4-new）。ベンチの主要指標は `gold_nll`
  **1本だけ**。`acc` / `acc_norm` / `margin` / `ref_kl` / `ref_agreement` は
  記述用に出すが、判定には使わない
- **主役の幅は4**（06 と同じ。幅2・3 は「幅が効く」ことの記述用）
- **判定**: 3 seed すべてで符号が改善方向、かつブートストラップ95%区間が
  0をまたがない → 「改良」と書く。PPL だけが満たしてベンチが null なら
  「PPL では改良、ベンチでは検出できず」と書く
- **対等な比較は「校正で選んだ一様」との差**である。この実験が答えるのは
  「50%にすればベンチでも見えるか」なので、報告の主語はこの1行になる
- **効き目の限界**: ブートストラップは問題や塊を再抽出するだけで、seed ごとに
  配分ベクトルが変わるぶんの分散は3本では測れない。そこは per-seed の符号一致
  （3/3 か）で補う。**ベンチで区間が0をまたいだままなのは、この設計では失敗
  ではない**（それが観測結果である）

## 対照を3つ置く

06 と同じ3つ。固定対照だけが A に連動して変わる。

| 対照 | 選び方 | 読み方 |
|---|---|---|
| `uniform2` | 固定 | 選び方に評価指標が入らない。A の半分＝ shared と routed が半々で、A=6 の `uniform3` と同じ立ち位置 |
| **校正で選んだ一様** | 一様5本を探索と同じ `suffix_kl` で採点した最良 | 両側とも「校正だけで選んだ1本」。**対等な比較はこれ** |
| 評価指標で最良の一様 | その指標を見てから5本の最良 | 探索に不利な側の下限 |

## 走らせ方

**本実行の前に必ず `--smoke` を通すこと。**

```bash
uv run python experiments/07_sparsity50/run.py --smoke   # 2層・2本・8問
uv run python experiments/07_sparsity50/run.py --seed 0  # 約3.6時間
uv run python experiments/07_sparsity50/run.py --seed 1
uv run python experiments/07_sparsity50/run.py --seed 2

# seed をまたいだまとめ（GPU 不要）
uv run python experiments/07_sparsity50/summarize_seeds.py --seeds 0,1,2
```

06 と違い、**seed 0 も探索から回す**。A が違えば探索の結果も違うので、
`result_logs/slimpajama_w*_n16_seed0`（A=6）は使えない。出力先の名前に `a4` が
入っているのはそのためで、A=6 の出力と混ざらない。

## 段と、済みの判定

1 seed は3段。**済んだ段は飛ばす**。印はファイルの存在ではない（開始直後から
真になる）ので、段ごとに中身を見る。

| 段 | コマンド | 出力 | 済みの印 |
|---|---|---|---|
| 1 探索 | `cmoe search` 幅2/3/4 | `slimpajama_a4_w<W>_n16_seed<N>/search.json` | `allocation` と `recheck` がある |
| 2 採点 | `cmoe score` 一様 x=0..4 | `score_uniform_slimpajama_a4_n16_seed<N>/score.json` | `best` があり、採点した本数が合う |
| 3 測定 | `cmoe run --bench` 8構成 | `bench_slimpajama_a4_seed<N>/summary.json` | `summary` と `bench_summary` があり、構成数が合い、`failures` が無い |

印の無いディレクトリは `*.partial<N>` へ退避してから引き直す（書きかけを「済み」と
取り違えない）。ただし**別の実験の出力**（引数が食い違う）だった場合は退避もせずに
止まる。`cmoe run` に途中再開は無いので、1構成でも失敗した段は全構成を引き直す。

## 見積もり（report/07 の実測からの外挿）

層ごとの候補が x=0..6 の7個から x=0..4 の**5個**に減るので、探索の評価回数は
5/7 になる（幅4 なら 875 → 625回）。測る構成も 10 → 8 に減る。

| 段 | A=6 の実測 | A=4 の見込み |
|---|---|---|
| 1 探索 幅2 / 3 / 4 | 35 + 53 + 69 = 157分 | 25 + 38 + 50 = **113分** |
| 2 一様の採点（1本 528 layer forwards） | 22分（7本） | **16分**（5本） |
| 3 測定（1構成 約11分） | 108分（10構成） | **86分**（8構成） |
| | 4.8時間 | **約3.6時間 / seed** |

seed 3本で**約11時間**。06 と違って seed 0 も丸ごと走る。

## 保存されるもの

- `slimpajama_a4_w<W>_n16_seed<N>/search.json` … 全層 × 全親 × 全候補のスコア、
  落選候補も含む枝の系譜、勝った配分の測り直し、校正の成分ごとの内訳
- `score_uniform_slimpajama_a4_n16_seed<N>/score.json` … 一様5本の score と層ごとの内訳
- `bench_slimpajama_a4_seed<N>/summary.json` … 全引数、PPL の塊ごとの平均 NLL を全件、
  ベンチの集計と対応のある比較
- `bench_slimpajama_a4_seed<N>/bench/run<NNN>_cmoe.json` … 問題ごと・選択肢ごとの
  生の対数尤度（fp32）。1構成 3.7MB
- `exp07_stages_seed<N>.json` … 段の一覧と、測ったコードのコミット
- `exp07_seeds/seeds.md` / `seeds.json` … seed をまたいだまとめ

指標を後から足すのに測り直しは要らない。`cmoe.eval.bench.load_samples()` で
読み戻せば、`bench_stats` の全指標が GPU なしで出る。
