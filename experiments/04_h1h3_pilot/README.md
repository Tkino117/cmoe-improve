# 04 H1〜H3 の下見（seed 1本）

## 目的

[docs/03](../../docs/03_expermient-design.md) の H1〜H3 を、seed 1本で通しで出す。
「一様配分より探索した配分の方が良い」が、どの一様配分に対して・どの評価セットで・
探索の幅をどこまで広げると成り立つのかを、まず形として見る。

有意性はここでは主張しない。区間は評価塊の再標本化のみで、seed の振り直しを
含まない。ばらつきの物差しは [report/01](../../report/01_calib-seed-variance.md)
（wikitext2・幅2・5本で標準偏差 0.0255）を借り、そこに埋もれない差がどこに出たかを見る。

## 仮説と、それぞれで測るもの

| | 校正データ | 測る配分 | 評価 |
|---|---|---|---|
| H1 | wikitext2 | 一様 x=0〜6 | wikitext2, c4-new |
| H2 | wikitext2 | beam 幅2 / 3 / 4 の探索結果 と 対照 uniform3 | wikitext2, c4-new |
| H3 | c4 | 一様 x=0〜6 と、beam 幅2 / 3 / 4 の探索結果 | wikitext2, c4-new |

H3 で一様配分も測り直すのは、**校正データが変わればモデルの組み方も変わる**ため。
H1 の一様（wikitext2 で組んだもの）を H3 の対照には使えない。

`cmoe run` が出す対応のある比較は、同じ run の先頭構成（uniform3）に対するものだけ
である。docs/03 の主張は「**どの**一様配分よりも良い」なので、集約側で
**探索配分 × 一様配分すべて**の突き合わせも作る。塊ごとの NLL が
`summary.json` に全件残っているので、これに GPU は要らない。

## 固定するもの

| | |
|---|---|
| モデル | meta-llama/Llama-2-7b-hf |
| N / A | 8 / 6（全構成で推論コストは同一） |
| nsamples / seqlen | 8 / 2048 |
| seed | 0（**探索用①と変換用②を揃える**。docs/03 の「同一のものを用いる」） |
| 採点オラクル | `suffix_kl` |
| 探索 | beam |
| router | cmoe |
| ブートストラップ | 10,000回 / seed 20260813 |

## 走らせ方

**本実行の前に必ず `--smoke` を通すこと。** H3 が使う c4 の校正経路はこの
リポジトリで本番実行された実績が無く、HuggingFace からの取得もそこで初めて走る。
2層だけの `--smoke` は同じ経路を10分で全部通る。

```bash
uv run python experiments/04_h1h3_pilot/run.py --smoke   # 2層だけの動作確認
uv run python experiments/04_h1h3_pilot/run.py           # 本実行（約4時間）
uv run python experiments/04_h1h3_pilot/run.py --stages h2   # 段を選ぶ
```

`--stages` で選ばなかった段も、済んでいればディスクから読んで集約に入る
（pilot.md から他の段が消えることはない）。

## 途中結果の残り方

段（探索1本 / 評価1回）ごとに別ディレクトリで、**完了印がある段は飛ばす**。

| | 完了印 |
|---|---|
| 探索 | `search.json` に `allocation` がある（探索の最後に書かれる） |
| 評価 | `summary.json` に `summary` があり、構成数が一致し、`failures` が無い |

印の無いディレクトリは `*.partial<N>` へ退避してから引き直すので、書きかけを
「済み」と取り違えない。ただし**別の実験の出力**（引数が食い違う）だった場合は
退避もせずに止まる。引数の一致は、結果を変えない引数（出力先・チャンク幅・
測り直しの有無）を除いた全引数で見る。

`cmoe run` に途中再開は無いので、1構成でも失敗した評価は次の起動で全構成を
引き直す（済んだぶんは `.partial<N>` に残る）。

wikitext2・幅2・seed 0 の探索は report/01 が済ませてある。引数が一致することを
確かめたうえで取り込み、出所を `reused_from.txt` に残す。

集約は `pilot.json` / `pilot.md`（測ったコードのコミットも記録する）。各校正の
uniform3 は2回組み直すことになるので、その2つが塊ごとの NLL まで一致するかを
決定性の点検に使う。
