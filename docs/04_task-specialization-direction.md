# 04 方向転換の案 — タスク特化

## 主張

- dense -> MoE の変換では、学習を一切せずにMoEに組み替えて、活性パラメータを減らす系統が現れた
- これらは変換後も汎用モデルであることを目標にしているが、実際の配備（特に計算量を減らす必要のあるエッジや組み込み）では、使用するタスクの種類は事前に決まっている
- タスク特化圧縮は(D-Pruner/LLM-Sieve/DieT?)などがすでに存在するが、それらのすべてが重みを削るため、タスクの数だけモデルを保持しなければならない
- 学習不要なMoE化は重みを一つも消さない。どのニューロンを常時使い、どのニューロンをどのエキスパートに割り当てるかという割当のみ行っており、それは校正データが決めている
- したがって、1つの重みの上にタスクごとの小さな設定を差し替えるだけで、特化モデルを切り替えることができる
- 示したいこと：タスクごとの校正でこの割当を決め直すだけで、denseとの差の相当部分を埋めることができる

## プルーニングとの比較

- プルーニングは提案手法の退化ケースである。x = A（Top-K = 0）のとき routing が消え、残った A/N のニューロンを常時使う静的マスクと一致する
- メモリ：負ける
- 速度：同程度
- 精度：原理的には下回らないはず

## 注意点
- ExpertWeaverなどの汎用性能を主張している論文で使われているデータセットとの比較は触れておく（勝たなければいけない）
- 実施はFFNの重み業の再配置を行うので、実務上の帯域については論文中でいい感じに触れておく

## 先行研究と、どこが空いているか

**校正データが効くこと自体は既知。** Williams & Aletras (ACL 2024, 2311.09755)、
Beware of Calibration Data (2410.17711)。多言語 pruning の TACL 版 (2408.14398) は
校正言語 × 評価言語の行列まで出しており、「ターゲット言語で校正しても下流は
一貫して改善しない」という否定的結果を報告している。

**「校正 ≫ 探索」と「PPL が下流と逆を向く」も既知。** Calibration Matters More
Than Search in LLM Depth Pruning (2604.24938) が depth pruning で両方を報告して
いる（探索7種の差は 1〜3 点、PPL 順位と下流順位の Spearman は −0.78〜0）。
report/11 の主要な2つの観察はこれと重なる。**主張の柱にはできない。**

**タスク特化圧縮も既にある。** D-Pruner (NAACL Findings 2024)、LLM-Sieve
(2505.18350)、DieT (2603.23985)、PuDDing (ICML 2025)、PreMoE (2505.17639)。
PreMoE はクロスドメイン行列まで出している（ただし元から MoE のモデルが前提）。

**dense→MoE 変換側。** CMoE は wikitext2 8サンプルで、Appendix D に「校正が対象
ドメインに合っているときに最良」と限界として書いてある（実験はしていない）。
ExpertWeaver は校正が Flan-v2（48タスク × 5-shot、240サンプル）で、C4 のみとの
ablation も済ませている（avg 67.0 vs 65.8）。結論は「多様性が重要」。
