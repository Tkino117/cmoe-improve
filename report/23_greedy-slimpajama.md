## 問い

[res15](icassp/res15-layer-interaction.md) の (b)「候補を1本に絞る（＝層ごとに
独立に確定する）と、目的関数も下流の `acc` も最も悪くなる」の根拠は
[report/11](11_*bench-calibration.md) の1系しかない。その校正は `benchtrain`
（5タスクの train split、n=8）で、`result_logs/` に `*_w1_*` は
`benchtrain_w1_n8_seed{0,1,2}` しか無かった。**校正を slimpajama n=16 に替えて
幅1 を測る。** 幅2・3・4 は report/07 に3 seed 揃っているので、足すのは幅1 だけ
である。

判定は走らせる前に1本だけ決めた —「**3 seed すべてで幅1 が最下位か**」。
探索が一様配分に勝つかは別の問い（report/07・res09）で、ここでは扱わない。

**尺度を層ローカルに替えた場合の貪欲は [report/24](24_local-oracle-greedy.md) に
ある。** 校正トークンが同じ（seed 0、`37738f7c8d47`）なので、この報告書の score と
同じ表に並べて読める。

## 設定

report/07 と同一。動かしたのは幅だけである。

| PPL | wikitext2 / c4-new |

| 所要 | 1 seed あたり 52.7 / 53.2 / 52.8 分（探索17.8分 + 測定3構成35分）、計 2.65時間 |

校正トークンのハッシュは seed 0 `37738f7c8d47`、seed 1 `f2d1aead2e61`、
seed 2 `432a411ed203` で、**report/07 の幅2・3・4 と同一**である（同じ seed の
行どうしは score を直接比べられる）。

段は2つ。

1. 探索 `cmoe search --search beam --width 1` → `slimpajama_w1_n16_seed<N>`
2. 測定 `cmoe run --bench` 3構成 → `bench_slimpajama_greedy_seed<N>`

段2 の3構成は `uniform3`（再現の検査）・幅4 の配分（対照）・幅1 の配分（候補）で、
**幅1 対 幅4 は同じ実行の中で測ってある**。幅2・幅3 は測り直していない。

```bash
uv run python experiments/26_greedy_slimpajama/run.py --seed 0   # 1, 2 も同様
uv run python experiments/26_greedy_slimpajama/summarize.py --seeds 0,1,2
```

`*` は 95% 区間が0をまたがない。PPL は seed を層とした評価塊の対応再抽出、

`acc` / `acc_norm` / `margin` / `ref_agr` は正が幅1 の勝ち、
`gold_nll` / `ref_kl` / NLL は負が幅1 の勝ち。
