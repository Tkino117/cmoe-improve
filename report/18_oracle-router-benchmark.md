# 18 オラクルルーターを選択問題ベンチマークで測る — acc は上がる

2026-09-01 / 出力 `result_logs/oracle_router_bench/`

## 問い

診断用オラクル `oracle_abs`（各 routed expert の `|h|` を**先に全部計算してから**
質量最大の Top-K を選ぶ。選択の前にその層が計算する H を作ってしまうので配備は
できない）は、PPL を大きく下げることが分かっていた
（`result_logs/anchor_E_uniform3_oracle_abs/`、wikitext2 6.638、seed 0 のみ）。

**ベンチマークは測っていなかった。** report/10 では配備できる5方式のどれ一つとして
`acc` で現行ルーターを上回らなかったので、「ルーティングを理想化しても `acc` は
動かない」のか「5方式が回収できた量が足りなかっただけ」なのかが、この測定の前は
区別できていない。

## 観察

数字がそのまま言っていることだけを置く。

- **`acc` は上がる。** マクロ +0.0221、区間は0をまたがない。タスク別でも5タスク中
  4つで区間が0をまたがず、下がったタスクは1つも無い。区間が0をまたぐのは
  WinoGrande の `acc`・`acc_norm`、ARC-c の `acc_norm` の3セルで、そのいずれでも
  同じタスクの `margin`・`ref_agreement`・`ref_kl` は0をまたがない。
- **PPL の改善（NLL −0.066 / −0.100）とベンチの改善が同じ向きに出ている。** これは
  report/04・07・08、および report/17 が配分側で繰り返し見てきた「PPL で勝っても
  ベンチでは出ない」とは違う出方である。
- **タスクごとの回収率は 17%〜53% とばらつく。** `acc` の回収率が最大なのは PIQA
  (53%)、最小は WinoGrande (21%) と ARC-e (22%)。
- **`oracle_abs` は `|h|` 回収率のオラクルであって、PPL や `acc` のオラクルでは
  ない。** ここで得た値は、選択を「質量最大」に理想化したときの1つの到達点であり、
  ルーティングで到達しうる上限そのものではない。
