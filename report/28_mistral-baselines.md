手法の中身（移送の範囲、原典と違えた点）は report/26 と report/21 に書いたもの
から変えていない。report/26 から変えたのは、モデルと、対照を測り直したこと
（次段）と、EW-rule を1本足したことの3つである。

**対照（現行 CMoE の分割）は測り直した。** report/26 は既存の
`bench_slimpajama*` を対照に流用したが、Mistral のそれは report/27 を測った
別マシン（RTX 6000 Ada ×4）の出力である。区別したい差の小さい側は `acc` で
0.003 程度しかなく、GPU が違うと浮動小数の積み方が変わって同じ桁の差が
出かねない。そこで比べる3つの配分（`uniform0` / `uniform1` / 提案 幅4）だけを
このマシン（RTX PRO 5000 Blackwell 1枚）で引き直し、**比較を1台に閉じた**
（`--method control`）。探索そのものは回し直していない — 配分ベクトルは
report/27 の探索結果をそのまま読んでいる。

**dense の基準だけは測り直していない**（`exp25_check` のものを取り込んでいる）。
dense との差は9〜24ポイントあり、この用途では測定環境の差は問題にならない。

**EW-rule の平均 x は、この2モデルで違う場所に落ちる。**

| EW-rule の平均 x | seed 0 | seed 1 | seed 2 | 同じ設定の提案 幅4 |
|---|--:|--:|--:|--:|
| Mistral（A=6 / A=4 共通） | 3.000 | 2.812 | 2.781 | A=6 で 4.09〜4.22、A=4 で 3.09〜3.25 |
| Llama（A=6 / A=4 共通） | 2.406 | 2.406 | 2.406 | — |

規則が出す x は {2, 3, 4} の3値で、A=4 でもクリップ（`[0, A]`）が起きないため
**A を変えても同じベクトルになる**（report/21 結果1 と同じ理由）。

A=4 では EW-rule と提案の平均 x がほぼ揃う（2.8〜3.0 対 3.1〜3.3）のに対し、
A=6 では1以上離れる。**50% の比較は平均 x が揃った条件での比較に近く、25% は
そうではない。**

## 結果3: 対応のある差

符号は「候補 − 対照」。`acc` は正、`gold_nll` は負が候補の勝ち。`*` は95%区間が
0をまたがない。`n/15` は候補が改善した (seed × タスク) の層数。

**対照 = 提案（beam 幅4）**

| スパース率 | 候補 | `acc` | `gold_nll` |
|---|---|--:|--:|
| 25% | EW-rule | −0.0030 [−0.0081, +0.0022] 6/15 | +0.017 [−0.006, +0.040] 8/15 |
| 25% | LLaMA-MoE-v2 @ uniform1 | −0.0025 [−0.0080, +0.0028] 8/15 | +0.037* 6/15 |
| 25% | LLaMA-MoE（Random）@ uniform0 | −0.0834* 2/15 | +4.878* 1/15 |
| 50% | EW-rule | −0.0177* 0/15 | +0.613* 0/15 |
| 50% | LLaMA-MoE-v2 @ uniform1 | −0.0255* 2/15 | +1.900* 0/15 |
| 50% | LLaMA-MoE（Random）@ uniform0 | −0.0446* 2/15 | +3.808* 0/15 |

**対照 = 現行 CMoE の分割（同じ配分）**

| スパース率 | 配分 | 候補 | `acc` | `gold_nll` |
|---|---|---|--:|--:|
| 25% | uniform0 | Random | +0.0030 [−0.0032, +0.0092] 8/15 | −0.591* 8/15 |
| 25% | uniform1 | v2 | −0.0030 [−0.0084, +0.0026] 6/15 | −0.014 [−0.040, +0.012] 10/15 |
| 25% | beam 幅4 | Random | −0.0864* 3/15 | +5.340* 1/15 |
| 50% | uniform0 | Random | +0.0173* 8/15 | −3.885* 8/15 |
| 50% | uniform1 | v2 | −0.0122* 2/15 | +1.094* 0/15 |
| 50% | beam 幅4 | Random | −0.0823* 1/15 | +13.200* 2/15 |

**対照 = 提案の行では** PPL の対応のある差（塊ごとの NLL、3 seed）も `gold_nll`
と同じ向きである。25% では 提案 → EW-rule が WikiText-2 で +0.008*、→ v2 が
+0.055*、50% ではそれぞれ +0.138*・+0.570*。一方、**同じ配分どうしの
25% `uniform0` だけは2つが逆を向く** — `gold_nll` は Random が良い（−0.591*）のに
WikiText-2 の NLL は Random が悪い（+0.814*）。`uniform0` は shared expert が
無い構成で、どちらの分割でも PPL が二桁まで崩れる領域である。

## 読み

**50% では提案が全ての比較手法に勝つ。** `acc` は「候補 − 対照」で EW-rule
−0.018*、v2 −0.025*、Random −0.045* と、いずれも候補側が負ける向きで区間が
0をまたがない。Llama（report/26）と同じ向きで、差の大きさも同じ桁である。

**25% では提案・EW-rule・v2 が横並びになる。** `acc` の差は −0.003 と −0.0025
で、どちらも区間が0をまたぐ。**Llama とここが違う** — 同じ 25% で、Llama では
提案が v2 に −0.0240*、EW-rule に −0.0095* と、どちらも区間が0をまたがなかった
（`experiments/28_llama_moe/compare.py` を Llama で流し直して確認した）。

ただし**分布の近さでは提案がなお勝っている。** v2 に対しては `gold_nll`
（+0.037*）と PPL（WikiText-2 の NLL +0.055*）の両方で、EW-rule に対しては
`gold_nll` は0をまたぐ（+0.017）ものの PPL では +0.008* で区間が0をまたがない。
**25% の Mistral は「正答率では差が付かないが、言語モデルとしての近さでは提案が
勝つ」**という読みになる。

この横並びは、25% が変換として易しい動作点であることと整合する。dense との差は
25% で 9.7 ポイント、50% で 24.3 ポイントあり、**手法の違いが出るのは厳しい側の
動作点である。** 論文の主張を「スパース率が上がるほど配分の決め方が効く」と
置くなら、この2動作点の対比はそのまま使える。

**LLaMA-MoE(Random) は、配分を提案と同じにすると壊れる。** 25% で `uniform0` の
ときは現行 CMoE と差が無い（+0.003、区間は0をまたぐ）のに、beam 幅4 の配分に
載せると −0.086* まで落ちる。50% でも同じ（+0.017* が −0.082* へ）。Llama も
50% は同じ形である（+0.0054 n.s. → −0.0865*）。ただし **Llama の 25% はこの形に
ならない** — `uniform0` の時点で既に −0.0171* で、beam 幅4 の −0.0249* との差は
小さい。

**原因は2つに割れていない。** 「shared expert を持つ配分と噛み合わない」のか、
「現行 CMoE の分割の上で探索した配分を、別の分割にそのまま移せない」のか、
ここで測った2点（`uniform0` と beam 幅4）では分離できない。Random を
`uniform4`（beam の平均 x 4.09〜4.22 の直下）で1点測れば分かれる。
