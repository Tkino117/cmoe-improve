## 問い

[report/21](21_ew-rule-baseline.md) で先行研究の対照は EW-rule 1本になった。
そこには2つ穴が残っている。

**穴1: 規則型が1本しか無い。** EW-rule が負けた理由が「層別スカラー → 単調写像
という方式そのもの」なのか「EW の既定 α が N=8 に合っていない」なのかを、
1本では分けられない。report/21 自身の注意点にそう書いてある。

**穴2: 平均 x が揃っていない。** EW-rule の平均 x は 2.41、提案は 4.60、
校正が選んだ一様は 5.67 である。差の一部は「層別に配分したこと」ではなく
「動作点が違うこと」で説明できてしまう。

対照を3本足してこの2つを埋める。**どれも提案手法ではない。**

## 3本の対照

### (1) 順序対照 — 平均 x を完全に揃える

提案（beam 幅4）が出した配分 `v` の**多重集合を保ったまま、層の並びだけを崩す**。
`reverse`（層順の反転）と `shuffle1` / `shuffle2`（独立な並べ替え2本）を置く。

これで次が全部同一になる。

- 1トークンあたりに走る expert 数 A（もともと x に依らない）
- 平均 x（同じ多重集合なので厳密に一致）
- x の度数分布そのもの（`x=6` の層が何本、`x=0` が何本）
- 校正データ・分割・ルーター・評価・dense の基準

違うのは**どの層にどの x が載るか**だけである。**この土俵で作れる最も強い対照**で、
差が出れば「層別に配分を決めることに意味がある」が言え、出なければ言えない。

実装 `src/cmoe/alloc/order.py`。一様配分（どう並べ替えても同じ）は例外で断る。

### (2) LExI 相当 — 層ローカルの出力誤差で決める

LExI (arXiv:2509.02753) は2段でできている。

1. **感度プロファイル。** 層 ℓ の active expert 数だけを動かし、**他の層は
   baseline のまま**にして、その層の出力の Frobenius ずれを測る
2. **予算制約下の探索。** `Σ_ℓ S[ℓ][k_ℓ]` を総 active expert 数の予算のもとで
   最小化する。原典はここを進化探索で解く

**移送で変わるのは 2 だけである。** この土俵では x に予算制約が無い（x が何でも
1トークンあたりに走る expert 数は A で一定）。制約が消えると和は層ごとに分離する
ので、**進化探索は層ごとの argmin に厳密に退化する**。原典の探索器を持ち込まない
のはそのためで、手を抜いたからではない。

1 の側は既存の `local_error` オラクルがそのまま使える。あれが測る

    L = Σ_t ‖ (h_t ⊙ missed_t) W_down^T ‖² / Σ_t ‖ h_t W_down^T ‖²

はその層の出力の相対二乗誤差そのもの（近似ではない）で、LExI の Frobenius ずれを
正規化した形である。**baseline を dense に取る**のが移送の要で、
`experiments/22_alloc_baselines/lexi_probe.py` が層を dense のまま進めることで
実現している。

**探索の `greedy` とは別物である。** あちらは変換済みの接頭辞の上を進むので、
層 ℓ の候補が層 0..ℓ−1 の選択に依存する。ここは全層 dense なので、どの層の表も
互いに独立になる。その差が「層ローカルか、後続まで通すか」の差であり、
**提案手法との差分が『尺度を suffix KL にした』の一点に絞られる**。

原典から違えた点はもう1つある。**LExI は感度を無作為な合成入力で取る**（data-free
を売りにしている）が、ここは他の行と同じ校正データの上で取る。理由は2つで、
(i) 実際の活性の方が合成入力より情報が多く、LExI を有利に扱うことになる、
(ii) 校正を揃えないと「配分の決め方だけを比べている」が崩れる。

実装 `src/cmoe/alloc/lexi.py`。同点の崩し方（x の小さい方＝ routing が多い側）を
記録に残す。

**移送の裏取りが取れている。** 作業ツリーには 8/25 に走らせた
`result_logs/order_local_error_{forward,reverse}_slim_n16_seed0` が残っている
（当時 CLI にあった `--order` は今のソースには無い）。`reverse` 側の注記が
「未決定の層は上流にあり dense として扱われる。層ローカルのオラクルは下流を
見ないので、層ごとのスコアは他の層の選択に依存せず、配分は幅にも層を回る順序にも
依らない独立な argmin になる」で、これは LExI の感度プロファイルそのものである。
**`lexi_probe.py` が出した配分は、その `reverse` の配分と 32 層すべてで一致した。**

同時に、`forward`（変換済みの接頭辞を進める貪欲）とは**層 27〜31 の5層で食い違う**
（`…,3,6,3,6,6` 対 `…,4,5,2,5,6`）。baseline を dense に取るか変換済みに取るかは、
この動作点で実際に答えを変える。

### (3) OWL 相当 — 別の層別統計を、EW と同じ写像に載せる

OWL (ICML 2024, arXiv:2310.05175) の式は2段。

1. Wanda スコア `A_ij = |W_ij| · ‖X_j‖₂`
2. 外れ値比率 `D_ℓ = |{A_ij > M · mean(A)}| / |A|`。M は既定 5

`D_ℓ` を EW-rule と**同じ写像**（`α_ℓ = α_max − (α_max−α_min)·s_ℓ`、
`x_ℓ = round(α_ℓ·N)`）に載せる。共通の器を `src/cmoe/alloc/score_rule.py` に
切り出したので、EW-rule も OWL-rule も `s_ℓ` の作り方だけが違う形になる。
**これが穴1 を埋める** — 規則型が2本になると、負けの原因を統計の質ではなく
方式の側に帰せる。

原典から違えた点は3つ。

- **統計を FFN の3枚（gate / up / down）だけで数える。** この土俵で動かすのは
  FFN の配分で、attention は一切触らない。attention の重みを混ぜると「配分の
  決め方」とは別の情報が入る
- **min-max で正規化する。** `D_ℓ` は 1e-3 の桁で、生のまま入れると α が α_max に
  張り付いて規則が一様配分に潰れる。OWL 自身も層別スパース率を `[S−λ, S+λ]` に
  再スケールしているので、値域を使い切るのが原典に沿う
- **向きは OWL の意味論から取る。** 外れ値の多い層ほど重要 → 削らない →
  routing を広く取る（x を小さく）。EW-rule の向き（特化した層ほど shared を
  減らす）と同じ形になる

**α レンジは EW-rule の既定と同じ `[0.2, 0.7]` を使う。** OWL には「この軸での
既定値」が原典に無い（原典が出すのは層別スパース率であって shared の割合では
ない）ので、N=8 という共通の制約のもとで2本の規則に同じ値域を与えるのが対等な
扱いである。

## 規則型の自由度をどう扱うか

**主表は原典の既定どうしで並べる。** EW-rule は τ=0.6・α=[0.2, 0.7]（report/21
と同じ）、OWL-rule は M=5・desc・α=[0.2, 0.7]。

そのうえで、**両方の規則に同じ格子を与えて校正だけで選び直した**行も測る
（`--stages ...,grid`）。片方だけ選び直すのは不公平だからである。選ぶのは
評価ベンチではなく校正データ上の `suffix_kl` で、これは提案手法が配分を選ぶのに
使っているのと同じ目的関数である — 評価ベンチを見て選ぶと、EW の既定値が
評価ベンチ上の掃引で決まっていることを批判している側が同じことをすることになる。
