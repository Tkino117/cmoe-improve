# 論文用 抜き出し: ExpertWeaver の配分規則との比較（report/21）

出どころ [report/21](../21_ew-rule-baseline.md) /
`result_logs/ew_bench{,_a4}_seed{0,1,2}`（EW-rule）と
`result_logs/bench_slimpajama{,_a4}_seed{0,1,2}`（対照）/ 新しい測定は無い

**§4 の比較手法の行。** 提案手法と同じ土俵に載る唯一の先行研究である。

## 何を比較したか

**ExpertWeaver 全体の再現ではない。** ここが移したのは
**層別配分を決める式(4)(5)(6) だけ**で、分割・ルーター・校正は提案手法の対照
（現行 CMoE / slimpajama）と同一に固定してある。比べているのは配分軸だけである。

EWと同一ではないので，EW-rule とか呼ぶと良さげ．

## 設定

res09 / res16 と同一。動かしたのは配分だけである。

| | |
|---|---|
| モデル / 層数 | `meta-llama/Llama-2-7b-hf` / 32 |
| N / A | 8 / 6（25%）・8 / 4（50%） |
| 校正 | slimpajama n=16 × 2048、seed 0 / 1 / 2 |
| 分割 / ルーター | 現行 CMoE（k_act 10 / bias_speed 0.001）。固定 Top-K |
| 評価 | PIQA / WinoGrande / ARC-e / ARC-c / HellaSwag、0-shot・全件 |
| ブートストラップ | 10,000回 / seed 20260813 |

**再現の検査を通してある。** 各 run に対照の一様配分を同梱し、既存の
`bench_slimpajama*` と突き合わせた結果、6本すべてで PPL の mean_nll と
macro `acc` が完全一致した（差 0、トークンハッシュ一致）。

## 注意点

* EW の規則は expert 粒度 64 前提であり、N=8 では表現力が落ちる。
α∈[0.2, 0.7] は `round(α·64)` なら x ∈ [13, 45] を細かく使えるが、
`round(α·8)` では {2,…,6} に潰れ、実際の CV 分布からは **{2, 3} の2値**しか
出てこない。
  * ただ特に本文で触れる必要はなさそう
