# 論文用 抜き出し: 層ローカルの指標では届かない（report/07・15・23・24）

出どころ [report/24](../24_local-oracle-greedy.md)（尺度の比較。2026-08-25 の測定を
2026-09-09 に記録）/ [report/15](../15_search-depth.md)（先読み）/
[report/07](../07_*slimpajama-alloc-3seeds.md)（幅2・3・4 と探索コスト）/
[report/23](../23_greedy-slimpajama.md)（幅1）/ 新しい測定は無い

**イントロ §3 後半（「ある層のみを対象として変換誤差を最小化したときに選ばれる
配分と、次の層まで含めて最小化したときに選ばれる配分が食い違う」）と §4 の
「後続まで通した誤差を尺度にし、候補を保持したまま層を進める」の根拠。**
res09 / res16 には入っていない部分。

証拠は3本ある。**(a) 同じ貪欲な歩き方でも、尺度を層ローカルにすると届く先が
ほぼ一様配分に戻る**、(b) 1層先を見てから刈ると刈る枝が変わる、(c) 尺度を固定
すれば、保持する候補を増やすほど目的関数が改善する。

**主張は「貪欲では届かない」ではなく「層ローカルの指標では届かない」である。**
幅1（貪欲）でも尺度が suffix KL なら一様配分には勝つ（(c) と下の「注意」）。
効いているのは探索の幅ではなく尺度の側で、(a) がそれを直接分離する。

## (a) 尺度を層ローカルにすると、ほぼ一様配分に戻る

report/24。**歩き方は両方とも幅1の貪欲で、校正トークンも同一**（slimpajama
n=16 × 2048、seed 0、ハッシュ `37738f7c8d47`）。違うのは尺度だけである。

| 配分の決め方 | 平均 x | `suffix_kl` | 最良の一様比 |
|---|--:|--:|--:|
| `uniform6`（seed 0 で最良の一様） | 6.00 | 0.192136 | — |
| 層ローカル誤差 + 貪欲（独立 argmin） | 5.75 | 0.190275 | −1.0% |
| 層ローカル誤差 + 貪欲（接頭辞） | 5.69 | 0.189543 | −1.3% |
| **suffix KL + 貪欲（幅1）** | 4.97 | **0.182807** | **−4.9%** |
| suffix KL + ビーム幅4 | 4.41 | **0.180591** | **−6.0%** |

**層ローカル誤差で決めた配分は、最良の一様を 1% 台しか下回らない。** 同じ幅1 の
歩き方でも、尺度を suffix KL にすると 4.9% 下回る。

**理由も測れている。** 層ローカル誤差は x について**32層中28層で単調非増加**で、
層ごとの argmin が **29/32 層で上限の x=6** になる。差が付く層でも2位との相対差は
中央値 2.3e-03（最小 1e-07 台）。つまりこの尺度は「どの層に shared を置くか」を
ほとんど区別せず、「全部 shared にせよ」と言う。出た平均 x 5.75 が `uniform6` の
隣にあるのはそのためである。

**論文でどう使うか。** §4 の LExI 相当（res22 の「層ローカル探索」の行）が
なぜ提案に届かないかの説明がここにある。res22 の LExI 相当が出す配分は、この
「独立 argmin」の行と32層すべてで一致する。

## (b) 1層先を見てから刈ると、刈る枝が変わる

report/15。**幅は据え置き（幅2）で深さだけを1段増やす**（`--lookahead 1`）。
子1つごとに次の層の候補を全部展開し、**その最良**を子の順位に使う — 層 ℓ と層 ℓ+1
の依存を見てから刈ることになる。校正・動作点・ルーター・評価・dense の基準は
report/07 と同一で、動かしたのは探索の深さだけ。

| seed | 深さ0 | 深さ1 | 差 | 平均 x（0→1） | x が違う層 | **先読みが最善を覆した行** |
|---|--:|--:|--:|---|--:|--:|
| 0 | 0.183640 | **0.180591** | −1.66% | 4.75 → 4.41 | 19/32 | **21/63** |
| 1 | 0.199688 | **0.194903** | −2.40% | 4.34 → 4.41 | 23/32 | **17/63** |
| 2 | **0.174962** | 0.176791 | +1.05% | 4.59 → 4.56 | 22/32 | **18/63** |
| 平均 | 0.186097 | 0.184095 | −1.00% | | | |

**右端の列が主張の中核である。** 63 行のうち 17〜21 行で、「その層だけを見た最善」と
「次の層まで見た最善」が食い違った。つまり**ある層の配分の良し悪しが次の層に依存
している場面が、探索の 3 割弱で実際に起きている**。イントロの「約 3 割の場面で
食い違う」はこの列である。

一方で score が改善したのは 3 seed 中 2 seed（seed 2 は +1.05% 悪化）で、先読みが
常に得とは限らない。**コスト**は 3 seed とも 54,257 `layer_forwards`（3,430 回）で、
深さ0 の 7,168（441 回）の **7.57 倍**。時間は 269分 対 35分。**幅で捉える方が
費用対効果が良い**という位置づけに使える — 幅4 は 14,112（幅2 の 1.97倍）で
同程度以上の score 改善を出している（(c) の表）。

**ベンチ**（3 seed 平均、対照は同 seed の深さ0）では `gold_nll` −0.031258\*、
`margin` +0.042150\*、`ref_agreement` +0.005260\*、`ref_kl` −0.009322\*、
WikiText-2 NLL −0.002306\*（3/3 seed）。`acc` は動かない
（−0.000510 [−0.005143, +0.003945]）。

## (c) 尺度を固定すれば、幅を広げるほど目的関数が改善する

report/07（幅2・3・4）と report/23（幅1）。slimpajama n=16 × 2048 で校正、
`suffix_kl`。**score は同じ校正トークンの上でしか比べられない**ので、seed を
またいで縦に読まない。

| seed | 最良の一様 | 幅1 | 幅2 | 幅3 | 幅4 |
|---|--:|--:|--:|--:|--:|
| 0 | 0.1921357（uniform6） | 0.182807 | 0.183640 | 0.181855 | **0.180591** |
| 1 | 0.2036013（uniform5） | 0.199620 | 0.199688 | 0.194681 | **0.193718** |
| 2 | 0.1838664（uniform6） | 0.177935 | 0.174962 | 0.174962 | **0.172759** |

- 12本すべてが、その seed で最良の一様を下回る。
- **幅3・幅4 は 3 seed とも幅1 を下回る**（幅1 は幅4 より +1.23% / +3.05% / +3.00%、
  平均 +2.42%）。
- **幅2 は幅1 に 2 seed で負ける。** 単調性は幅2 以上でしか言えない
  （幅2→3→4 は 3 seed とも単調非増加、seed 2 の 幅2→幅3 のみ同値）。
- 非決定性の床は全 seed 0.000e+00。勝った配分を測り直した差も 0。

**探索予算は単調なトレードオフとして扱える。** コストは幅ごとに一定で、
幅1 が 3,696 `layer_forwards`（224 回 / 17.7分）、幅2 が 7,168（441 / 35.4分）、
幅3 が 10,640（658 / 52.7分）、幅4 が 14,112（875 / 70.3分）。一様1本の採点は 528。
§4 の「調整対象は探索の予算のみ」を数字で言える箇所。

**下流でも幅は効く**（report/23、3 seed、幅4 対 幅1 を同じ実行の中で測定）。
WikiText-2 NLL +0.004910 [+0.003153, +0.006636]\*、C4-new NLL +0.002797
[+0.000992, +0.004603]\*（どちらも 3/3 seed で幅4 の勝ち）。**ベンチの6指標は
すべて区間が0をまたぐ**（`acc` は +0.000661 [−0.003859, +0.005062]）。

## 注意

- **「幅1（貪欲）が最も悪い」とは書けない。** report/11（`benchtrain` 校正、n=8）
  では幅1 が 3 seed とも最下位だったが、**slimpajama 校正（n=16）で測り直すと
  最下位は 3 seed 中 1 seed だけ**で、2 seed では幅1 が幅2 を上回る（report/23）。
  幅1 は `uniform3` にも勝つ（`acc` +0.005508\*、PPL 3/3 seed）。report/11 で
  幅1 が `uniform4` に `acc` −0.0033 で負けていたのとは逆である。**この順位は
  校正に依存する。**
- したがって §3 の主張は **(a) の尺度の比較**に置く。幅の話は (c) の
  「幅3・幅4 が 3 seed とも幅1 を下回る」までで、「幅について単調」とは言わない。
- **3本は校正データが違う。** (a)(c) は slimpajama n=16 × 2048、(b) も同じ。
  report/11 だけが `benchtrain` 8 × 2048 で、`suffix_kl` の値を並べてはいけない。
- **(a) は seed 0 の1本、ベンチは測っていない。** ただし「独立 argmin」の配分は
  res22 の LExI 相当と一致するので、下流の数字はそちらが持っている（3 seed ×
  2動作点）。査読で seed 数を問われたらそちらを指す。
- **(a) のコストは縦に比べられない。** 層ローカルは後続の層を走らせないので
  単位が違う（`layer_ffn_evals` 対 `layer_forwards`）。比べられるのは評価回数と
  時間で、幅1 どうしなら 224回 対 224回・12.5分 対 17.7分である。

## 論文でどう並べるか（案）

1. **図1**（`report/figures/fig_allocation_bands.pdf`）で「尺度を層ローカルにすると、
   届く先が最良の一様の隣まで戻る」→ §3 の観察2 の前半と、§4 の LExI 相当が
   負ける理由。**本文に残す数字は「約3割」1つだけ**で、(a) の表の値は §4 の
   比較表（LExI 相当の行）に任せる。
2. **(b) の『先読みが最善を覆した行』**で、層間依存が起きている回数を直接示す
   （イントロの「約 3 割」）→ §3 の観察2 の後半。
3. **(c) の表**で「尺度を固定すれば、保持する候補を増やすほど改善し、コストは
   単調に増える」→ §4 の「調整対象は探索の予算のみ」。
