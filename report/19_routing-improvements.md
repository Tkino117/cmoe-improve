# 19 ルーティングを2箇所いじる — 低ランクの質量見積もりと、可変 Top-K

2026-09-01 / 実験 `experiments/19_spectral_router/` /
出力 `result_logs/spectral_r{8,32,128}_seed0`、`result_logs/dynamic_ppl_seed0`、
`result_logs/spectral_router_bench`

## 問い

[report/18](18_oracle-router-benchmark.md) は、配備できない診断用オラクル
`oracle_abs`（各 routed expert の `|h|` を先に全部計算してから質量最大の Top-K を
選ぶ）が選択問題の `acc` をマクロ +0.0221 上げることを示した。
[report/10](10_router-methods-benchmark.md) で測った配備できる5方式は、どれも
`acc` を動かせなかった（区間が全部0をまたぐ）。

**その差を埋められるか。** 埋めるなら、どこをいじるか。

## 測った2つの変更点

report/10 の5方式はどれも「expert を代表する実在ニューロン1本」と「どのトークン
にも K 個」の2つを共有していて、動かしていたのは前者だけだった。ここではその
2つを1つずつ外す。

* **軸A: score を、和そのものの近似にする**（方式7 `spectral_mass`）。オラクルが
  読んでいるのは
  $S_e(x) = \sum_{i \in e} \lvert \mathrm{silu}(g_i \cdot x)(u_i \cdot x) \rvert$
  という expert 内の全ニューロンの和である。その上界
  $\lVert \mathrm{silu}(G_e x) \rVert \cdot \lVert U_e x \rVert$ を重み行列の
  低ランク近似で作ると、$2 r \times \mathit{hidden}$ の積和で和を見積もれる。
  学習は無く、基底は特異値分解1回、行の重みは校正データ上の平均1回で決まる。
* **軸B: 固定 Top-K をやめる**（方式8 `dynamic_cmoe` / `dynamic_spectral`）。
  score のしきい値を層ごとに1個決め、平均だけを予算に合わせる。しきい値は校正
  データ上で平均が K になるように取る。**軸B には追加の積和が1回も無い。**

2方式が何をしているかは [report/20](20_routing-algorithms.md) に分けて書いた。
このレポートは測った数字を記録する。

## 結果1: オフラインの探査（9層、モデルを走らせない）

`experiments/19_spectral_router/probe.py`。層 0/3/7/11/15/19/23/27/31 の
validation 軌道の上で、score 関数だけを差し替えて採点したもの。`err` は
その層の出力誤差
$\lVert y_{\mathrm{dense}} - y_{\mathrm{sel}} \rVert / \lVert y_{\mathrm{dense}} \rVert$
（配分オラクル `local_error` と同じ量）である。**この節の数値は保存していない**
— 材料が1層 539 MB あるので `result_logs/` に置いていない。再現は `dump.py` →
`probe.py` / `dynamic_k.py`（コマンドは実験の README にある）。

`一致率` はオラクルと Top-K 集合がそのまま一致したトークンの割合、`質量` は選んだ
expert が回収した活性質量 $\sum_i \lvert h_i \rvert$ の割合、`gap回収` は方式1 を
0・`oracle_abs` を 1 としたときの `質量` の位置（report/18 と同じ定義）。

| score | 一致率 | 質量 | gap回収 | err |
|---|--:|--:|--:|--:|
| 方式1 `cmoe` | 0.1035 | 0.7796 | 0.0% | 0.3605 |
| 代表を上位 m=32 本に増やす | 0.1765 | 0.7812 | 24.3% | 0.3554 |
| 方式7 rank 32（白色化あり） | 0.2714 | 0.7826 | 45.8% | 0.3552 |
| 方式7 rank 128（白色化あり） | 0.3460 | 0.7835 | 60.5% | 0.3512 |
| $\lVert \mathrm{silu}(G_e x) \rVert \cdot \lVert U_e x \rVert$（低ランクにしない） | 0.4783 | 0.7847 | 78.7% | 0.3423 |
| `oracle_abs`（配備できない） | 1.0000 | 0.7861 | 100% | 0.3392 |

**関数形の天井は 78.7% で、低ランク近似がそこからさらに削る。** 代表を32本に
増やすより、同じ本数ぶんの積和を低ランクに使う方が良い（24.3% → 45.8%）。

同じ9層で、固定 Top-K をやめたとき（`dynamic_k.py`。しきい値は fit の上で平均が
3になるように決め、validation で当てた。`mean_k` はその実測である）。低ランクの
行は**白色化を切った基底**で、これは可変Kが score の絶対値を読むためである
（理由はこの節の後半）:

| score | 配り方 | mean_k | 質量 | err |
|---|---|--:|--:|--:|
| 方式1 `cmoe` | 固定K | 3.000 | 0.7796 | 0.3605 |
| 方式1 `cmoe` | 可変K | 3.005 | 0.7875 | 0.3529 |
| 低ランク rank 32（白色化なし） | 固定K | 3.000 | 0.7819 | 0.3562 |
| 低ランク rank 32（白色化なし） | 可変K | 2.998 | 0.8098 | 0.3230 |
| 低ランク rank 128（白色化なし） | 可変K | 2.995 | 0.8155 | 0.3097 |
| `oracle_abs` | 固定K | 3.000 | 0.7861 | 0.3392 |
| `oracle_abs` | 可変K | 3.022 | 0.8252 | 0.2915 |
| 出力寄与のオラクル $\lVert \mathrm{down}_e h_e \rVert$ | 可変K | 2.985 | 0.8195 | 0.2858 |

**追加の積和ゼロという制約の下では、配り方を変える方が大きい。** 現行の score の
まま配り方だけ変えると err は 0.3605 → 0.3529（−0.0076）で、これは積和が1回も
増えない。score だけを変えて配り方を固定した場合は 0.3512（−0.0093、rank 128 で
積和 5.17% 増）で、動く量は同程度だがコストが違う。

**2つを合わせると、固定Kのオラクルより小さくなる。** rank 32 の可変Kが 0.3230、
rank 128 の可変Kが 0.3097 で、どちらも **`oracle_abs` の固定K（0.3392）を下回る**。
可変Kのオラクル（0.2915）と出力寄与のオラクル（0.2858）はさらに小さい。

トークンごとに規格化する配り方（score をその行の和や最大値で割ってからしきい値を
当てる。D2DMoE の dynamic-k は後者の形である）は、3層の予備測定では固定Kと
変わらなかった — オラクルの質量が、和で割ると 0.7766、最大値で割ると 0.7749 で、
固定Kの 0.7769 を**どちらも超えない**。同じ条件で絶対値のまま配ると 0.8091 に
なる。効いているのは score の**絶対値**である。

**白色化は可変Kでは切る。** 校正データで基底を選ぶと、その校正データの上でだけ
score が持ち上がる。固定 Top-K は順位しか読まないので気付かないが、しきい値は
絶対値を読むので、fit で決めたしきい値が評価データでずれる — 3層の予備測定では
平均 K が 3.00 から 2.69 へ落ち、err はむしろ悪化した（0.4091 → 0.4262）。

## 観察

数字がそのまま言っていることだけを置く。

- **`dynamic_cmoe` の `acc` は区間が0をまたがない**（+0.005575
  [+0.000898, +0.010225]）。report/10 で測った配備できる5方式は `acc` の区間が
  全部0をまたいでいたので、**そこを通った配備できるルーターはこれが最初**である。
  ルーターの積和は方式1 と1回も違わず、走った expert 数はむしろ少ない。
- **`spectral_mass:128` の `acc` は区間の下端が −0.000071 で、わずかに0をまたぐ**
  （+0.004746）。点推定は方式8 と同じ大きさだが、判定は付かない。
- **2方式とも `gold_nll` / `margin` / `ref_agreement` / `ref_kl` の4つで区間が
  0をまたがない。** 壊した量（`ref_kl`）と正解の確からしさ（`gold_nll`）は
  どちらも `acc` よりはっきり動いており、この向きは report/18 のオラクルと同じ
  である。
- **PPL でも、report/10 で配備できる方式が出した最良を両データセットで上回る。**
  方式4 は NLL −0.009930 / −0.001020（3 seed、同じ対照）だった。方式7 は
  −0.029179 / −0.031189、方式8 は −0.021210 / −0.019938 で、どれも区間が
  0をまたがない。`oracle_abs`（−0.065920 / −0.099711）に対する割合は、方式7 が
  44% / 31%、方式8 が 32% / 20% である。
- **オラクルに対する回収率。** dense と方式1 の差に対して `oracle_abs` が埋めた
  割合は `acc` で 33.5% だった（report/18）。同じ分母で方式8 は 8.4% を埋めて
  いる。方式7 も点推定では 7.2% だが、**そのもとになる `acc` の区間は0をまたぐ**。
  `gold_nll` では方式7 が 11.3%、方式8 が 8.6% で、こちらはどちらも区間が
  0をまたがない。
- **PPL の順序と `acc` の順序が一致していない。** 方式7 は PPL で方式8 を
  はっきり上回る（NLL −0.0292 対 −0.0212、区間は重ならない）が、`acc` の点推定は
  +0.004746 対 +0.005575 で逆向きである。ただし**この2方式どうしの差は測って
  いない** — どちらの区間も対照に対するもので、互いの差の区間ではない。
