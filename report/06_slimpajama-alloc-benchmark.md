# 06 混合コーパスで校正した配分を、ベンチマークで測る

2026-08-23 / 出力 `result_logs/bench_slimpajama_seed0`

## 目的

[report/05](05_slimpajama-calibration-allocation.md) が slimpajama 校正で出した
探索配分3本を、report/04 と同じベンチマークにかける。

## 設定

校正は slimpajama n=16 の seed 0（`37738f7c8d47`）。引き方は report/05 に書いた
とおりで、7成分を層化して引いた 16本 × 2048トークン。

| | |
|---|---|
| モデル / 層数 | `meta-llama/Llama-2-7b-hf` / 32 |
| N / A | 8 / 6（スパース率25%。全構成で同一） |
| 配分 | 一様 x=0〜6 と、report/05 の beam 幅2 / 3 / 4 |
| ルーター / 分割 | 現行 CMoE（k_act 10 / bias_speed 0.001） |
| ベンチ | PIQA / WinoGrande / ARC-e / ARC-c / HellaSwag、0-shot・全件、batch 32 |
| PPL | wikitext2 / c4-new |
| ブートストラップ | 10,000回 / seed 20260813 |
| 環境 | RTX PRO 5000 Blackwell、Python 3.11.14 / PyTorch 2.8.0+cu128 / transformers 4.47.1 / datasets 2.21.0 / lm-eval 0.4.12 |
| コード | `1ccca42` |
| 所要 | 108.2 分（10構成、1構成あたり 10.8 分）。失敗0 |

**seed は1本だけである。** report/04 は seed 3本で出している。

dense の基準は測り直さず、report/04 のもの
（`result_logs/bench_h4/wikitext2_seed0/bench/dense.json`）を取り込んだ。dense は
変換していないモデルなので校正データに依らない。取り込み元は `dense_from.txt` に残る。

指標は report/04 と同じ6つ（`acc` / `acc_norm` / `gold_nll` / `margin` /
`ref_kl` / `ref_agreement`）で、残してあるのは問題ごと・選択肢ごとの生の対数尤度である。

```bash
uv run cmoe run --calib slimpajama --nsamples 16 --seeds 0 \
  --datasets wikitext2,c4-new --bench --bench-batch-size 32 \
  --bench-reference result_logs/bench_h4/wikitext2_seed0/bench/dense.json \
  --alloc uniform3 --alloc uniform0 --alloc uniform1 --alloc uniform2 \
  --alloc uniform4 --alloc uniform5 --alloc uniform6 \
  --alloc <幅2 の配分> --alloc <幅3 の配分> --alloc <幅4 の配分> \
  --out result_logs/bench_slimpajama_seed0
```

## 保存されているもの

`result_logs/bench_slimpajama_seed0/`。

- `summary.json` … 全引数、PPL の塊ごとの平均 NLL を全件、ベンチの集計と
  対応のある比較、校正の成分ごとの内訳
- `bench/run<NNN>_cmoe.json` … 問題ごと・選択肢ごとの生の対数尤度（fp32）、
  `doc_hash`、正解番号、選択肢の文字数、lm-eval 自身の集計値
- `bench/dense.json` … dense の基準（取り込み。出所は `dense_from.txt`）
- `run.txt` … 表示したものすべて

指標の付け替えも、別の対照の取り方も、`cmoe.eval.bench.load_samples()` で
読み戻して GPU なしで計算できる。
