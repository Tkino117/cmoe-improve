## イントロ

### 1. 分野の背景

大規模言語モデルの推論コストは、その実用化における主要な制約となっている。この制約を緩和する有力な方向の一つが、Mixture-of-Experts (MoE) による条件付き計算である。しかし既存の MoE モデルは大規模な事前学習を前提としており、既に学習済みの dense モデルを MoE 化するには、通常は多大な再学習コストを要する。そこで近年、再学習を伴わずに dense モデルを MoE へ変換する training-free なアプローチが提案されている [CMoE, EW]。これらは FFN のニューロンを、全トークンで常時起動する shared expert と、選択的に起動する routed expert に分割し、1 トークンあたり A 個の expert のみを起動することで、総パラメータ量を保ったまま実効的な計算量を削減する。勾配計算を一切必要とせず、少量の校正データのみで完結するため、再学習の敷居が高い大規模モデルに対して特に実用的な意義を持つ。

### 2. 課題: 起動予算が一様に割り付けられている

この「1 トークンあたり A 個」という起動予算は、本来は総量に対する制約である。しかし既存手法は、これを二重の一様性によって満たしている。第一に、各層で shared と routed に何個ずつ割くかという内訳が、層による役割の差異を考慮しないまま全層一律の値として与えられる [CMoE]。第二に、routed から起動する個数が、どのトークンに対しても厳密に K 個に揃えられる（Top-K）。

どちらの一様性も、予算そのものが要求しているものではない。とりわけ Top-K は、予算より強い制約である。予算は平均して K 個であれば足りるところを、Top-K は全てのトークンに例外なく K 個を課しており、routed 側をほとんど必要としないトークンと強く必要とするトークンを区別できない。層方向の一様性についても同様に、層ごとに内訳を変える自由度は制約の内側に残されたままである。

この自由度に既存手法が踏み込めていないのは、決め方が無いからである。層別の内訳を導入した ExpertWeaver [EW] でも、その探索範囲を規定するしきい値と上下限は経験的に固定されており、結果はその設定に依存する。トークンごとに個数を変える手法 [D2DMoE, DynaMoE, TopP] は、いずれもルーターの学習ないし fine-tuning を前提としており、training-free の設定に前例がない。

共通の原因は、校正データを分割やルーティングの根拠となる統計量の算出にのみ用い、構成された結果を評価して決定に反映させる過程を持たないことにある。構成手続きが一方向であるため、残された設計判断は定数か人手の調整で埋めるほかない。

### 3. 実験による観察: どちらの方向も、局所を見ては決まらない

一様性を外す自由度が二方向にあるとして、それぞれをどう決めるべきか。我々の観察は、両方向が同じ形の失敗を共有していることを示す。

**層方向。** shared/routed の一様な内訳が最良となる値は評価データによって異なり、単一の固定値が普遍的に最適とはいえない。かといって、層ごとに独立に最良の内訳を選ぶ素朴な貪欲法は、一様配分に対して明確な改善をもたらさない。一方で、探索時に保持する内訳候補の数を増やすほどオラクルのスコアは改善する傾向がある。すなわち、ある層の内訳の良し悪しは他の層に依存しており、その層だけを見て生じた誤差が後続の層に吸収されるのか増幅されるのかは言えない。層ローカルな指標では決められず、決められるのは変換後のモデル全体の出力分布が dense からどれだけ乖離するかである。

**トークン方向。** 起動個数を Top-K から解放する配り方は何通りもあるが、効くのは一通りだけである。平均個数を K に固定したまま、配備できないオラクルの score で四通りを比較すると、score をそのトークン内の和ないし最大値で正規化してからしきい値を当てる配り方は、いずれも固定 Top-K を上回らない。後者は既存の dynamic-k [D2DMoE] が採る形である。上回るのは、score を正規化せず絶対値のまま全トークンにわたって配ったときだけである。すなわち効いているのは各トークンの score ベクトルの形ではなく大きさであり、softmax と Top-K はこの情報をちょうど捨てている。この帰結は事後的なものではない。CMoE 自身の目的である非活性 expert の活性質量の最小化を、平均 K 個という予算制約の下で厳密に解けば、解は Top-K ではなく score の大域しきい値になる。Top-K は、この目的を各トークンへ等分するという追加の制約を暗黙に置いていたことになる。

二つの観察は同じことを言っている。**局所的な視点——層ローカルな誤差、トークン内で正規化した相対的な score——では、一様割付に勝てない。改善が現れるのは、層をまたいだ最終出力と、トークンをまたいだ score の絶対値という、全体を見た量に依拠したときだけである。** したがってこの問題は代理指標の改良では解決されず、両方向とも校正データ上で全体を測りながら決める手続きを要する。

### 4. 提案: 予算はそのままに、配り方を校正データから決める

本論文では、1 トークンあたり A 個という起動予算を保ったまま、その割り付けのみを校正データから決定する二つの手続きを提案する。

層をまたいでは、層別の shared/routed 内訳を、校正データ上で dense モデルの出力分布との KL ダイバージェンスを最小化する探索問題として定式化する。層間の相互作用を捉えるため、層ごとに独立に確定させるのではなく、複数の内訳候補を幅 B 本保持したまま層を進める beam search を用いる。

トークンをまたいでは、routed の起動個数を Top-K から解放し、softmax を通す前の score をしきい値 τ と比較して選択する。τ は、校正データ上で平均起動個数がちょうど K となる分位点として層ごとにスカラー 1 個で一意に定まり、学習を要しない。推論時には各トークンが自身の score を τ と比べるだけで、他のトークンを参照しない。

この提案は、性能を左右する経験的なしきい値を新たに導入しない。調整対象は探索の予算 B のみであり、これは計算量と品質の間の単調なトレードオフとして扱える。τ は起動予算から決まる従属量である。また、推論時の積和は 1 回も増えない。beam search は変換時に一度だけ実行され、しきい値は既に計算されている score の読み方を変えるだけである。起動個数は平均でしか予算を守らないため実測を要するが、後述するように評価データ上で実際に起動された expert 数は予算を下回っており、対照より少ない計算で改善が得られている。重みの値自体は変更せず構成のみを決定するため、fine-tuning とは競合せず、その前段として併用できる。

### 5. まとめ

本論文の貢献は以下の通りである。

- training-free な MoE 変換において一様に固定されていた二つの割り付け——層ごとの shared/routed 内訳と、トークンごとの routed 起動個数——を、固定された起動予算の下で校正データから決定する設計変数として定式化する。
- どちらの方向も局所的な指標では決められないことを示し、層方向には出力分布の KL を目的とする beam search、トークン方向には予算から一意に定まるしきい値という、新たな経験的パラメータを導入しない二つの手続きを提案する。
- Llama-2 7B において、追加の推論コストなしに、親モデルへの忠実度と選択問題の指標が一貫して改善することを示し、fine-tuning との併用可能性を示す。

## 手法

### 1. 準備: CMoE 型の dense-to-MoE 変換

CMoE は、学習済みの dense モデルの FFN 層を、追加学習なしに MoE 化する。各層の FFN において、校正データに対する各ニューロンの活性化頻度を測り、頻度の高い上位のニューロンを shared expert として全トークンで常時起動させる。残りのニューロンは活性化パターンが似たものどうしでクラスタリングし、N_r 個の routed expert に分割する。各 routed expert について、そのクラスタの重心に最も近いニューロンを代表ニューロンとして選び、対応する重み列だけを残した縮約ゲートでルータースコアを近似する。推論時には、このスコア上位 Top-K の routed expert だけを追加で起動する。総パラメータ数は dense モデルと同一のまま保たれ、1 トークンあたりに実際に計算される expert 数、すなわち shared 数 x_ℓ と routed の Top-K_ℓ の和 A = x_ℓ + K_ℓ は、全ての層で共通の値に固定される。

配分 x_ℓ（0 ≤ x_ℓ ≤ A）は層ごとに独立に選べる自由度だが、CMoE は全層で同一の値 x_ℓ = x を用いる。層ごとの配分を導入した ExpertWeaver も、その決定に使う探索範囲のしきい値パラメータ自体は経験的に固定したままである。以降では、この配分ベクトル x = (x_1, ..., x_L) を校正データから直接決定する問題として定式化する。

### 2. 配分探索の定式化

配分 x_ℓ の良さは、変換後のモデルの出力分布が dense モデルの出力分布からどれだけ乖離するかで測るのが自然である。各層の出力誤差のような層ローカルな指標は、その層だけを見て、生じた誤差を後続の層が吸収するのか増幅するのかを言えない。3節の観察が示すように、層間にはこの伝播を無視できない相互作用がある。

そこで、層 0 から ℓ までを配分 (x_1, ..., x_ℓ) で変換した MoE とし、残りの層 ℓ+1 以降は dense のまま実行して得られる出力分布を P_接頭辞、完全な dense モデルの出力分布を P_dense とし、校正データのトークン平均 KL ダイバージェンス

  score(x_1, ..., x_ℓ) = Σ_t KL( P_dense(t) ‖ P_接頭辞(t) ) / T

を接頭辞のスコアとする。残りの層を dense で置き換える仮定を含むため、これは ℓ < L-1 では見積もりに過ぎず、ℓ = L-1（全層決定後）でだけ、実際に配備されるモデルの KL と一致する。目的は、各層で A 個の expert を起動するという制約 x_ℓ + K_ℓ = A（∀ℓ）のもとで、この最終スコアを最小化する配分 x* を求めることである。

### 3. beam search による探索

上記の目的関数を層 0 から順に評価しながら、良い接頭辞を幅 B 本だけ残して層を進める beam search により x* を近似する。層 ℓ では、幅 B 本の接頭辞それぞれについて次候補 x_{ℓ+1} ∈ {0, ..., A} をすべて試して子を作り、子をスコアで並べ替えたのち上位 B 本だけを残して層 ℓ+1 に進む。この操作を L 層分繰り返した末に残る 1 本を最終的な配分として出力する。ある層で捨てられた接頭辞は、以降どれだけ良い枝を持っていても復元されない。B=1 のときは、各層でその場のスコアが最良の 1 本だけを残す貪欲な歩き方に退化する。3節で観察した貪欲法の失敗は、この幅の下限に相当する。

子 1 つの評価は、その子から残りの層を dense として走らせる forward を要するため、層 ℓ の子 1 つあたりのコストは L-ℓ に比例する。したがって全体のコストは幅 B・候補数 A+1 に対して線形、層数 L に対しては L² のオーダーで増える。B は探索の予算そのものであり、増やすほど良い配分を見つけやすくなる一方、この計算コストとのトレードオフになる。

### 4. 性質

この探索は、CMoE や ExpertWeaver が導入していたような、性能を左右する新たな経験的しきい値を一切導入しない。唯一の調整対象は探索の予算 B であり、計算量と発見される配分の質との単調なトレードオフとして扱える。探索はモデル変換時に一度だけ実行され、得られる配分自体は CMoE と同じ形式の expert 構成であるため、**推論時の計算量やパラメータ数は変化しない**。また、この手続きは既存の重みの値を一切変更せず構成のみを決定するため、fine-tuning による後段の調整とは独立に適用でき、両者は競合しない。
