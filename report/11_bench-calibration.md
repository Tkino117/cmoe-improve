# 11 校正データをベンチマークの train split に替える

2026-08-28 / 出どころ `result_logs/bench_benchtrain_seed{0,1,2}`、
`result_logs/benchtrain_w{1,2,3}_n8_seed{0,1,2}`、
`result_logs/score_uniform_benchtrain_n8_seed{0,1,2}` /
対照は [report/04](04_alloc-search-benchmark.md) の wikitext2 校正
（`result_logs/bench_h4/wikitext2_seed{0,1,2}`）

## 目的

CMoE は「どのニューロンを常時使い、どれを切り替えるか」を、**校正データ**と
呼ぶ少量のテキスト（ここでは 16,384 トークン）を1回流して決める。これまでの
校正はすべて素の文章（WikiText-2 / C4 / SlimPajama）だった。一方で最後に測る
のは5つの選択問題ベンチマークである。

素の文章から切り出した窓は、文の途中から始まって単語の途中で終わり、2048
トークンのあいだに話題が何度も変わる。選択問題でモデルが読むのは、数十トークン
の独立した1問である。**この食い違いを埋めると何か動くのか**を見た。

## 設定

### 変えたもの

校正セットだけを `benchtrain` に替えた。5タスク（PIQA / WinoGrande / ARC-e /
ARC-c / HellaSwag）それぞれの **train split** から問題を引き、1問を
「問題文 + 正解の選択肢」という1本のテキストに直して連結し、そこから 2048
トークンの窓を切る。

**評価に使う split には1問も入らない。** lm-eval が採点に使うのは PIQA /
WinoGrande / HellaSwag が validation、ARC が test で、校正が読むのはそのどれ
でもない。したがって report/04 の測定と dense の基準はそのまま対照に使える。

タスクごとの本数は seed に依らず固定である（n=8 なら PIQA 2 / WinoGrande 2 /
ARC-e 2 / ARC-c 1 / HellaSwag 1）。ベンチの集計がタスクを等しく重み付ける
マクロ平均なので、校正の側もタスクを等しく扱う。

seed 0 で実際に引けたのは、5タスクから 3,503 問・16,384 トークンだった。

### 変えなかったもの

Llama-2-7B / 32層、N=8 expert・A=6（スパース率25%）、現行 CMoE ルーター、
校正 n=8・seqlen 2048、採点オラクル `suffix_kl`、評価は WikiText-2 と C4-new の
PPL と5タスクのベンチ（0-shot、全問）、ブートストラップ 10,000 回。dense の
基準は report/04 のものを取り込んだ（dense は変換していないモデルなので、校正
にも seed にも配分にも依らない）。

### 走らせる前に決めたこと

- 主判定は `gold_nll` と `ref_kl`。`acc` は report/07 で効果量 0.005・区間の
  半幅 0.005 と桁が足りないことが分かっていたので、判定には使わない
- WikiText-2 の PPL 悪化は仮説の否定にならない（校正がそこから離れるため）
- 校正どうしの比較は同じ配分どうしで取る。ここでは `uniform4`

### 所要

1 seed あたり 131 分（探索3幅 → 一様3本の採点 → 6構成の測定）、3 seed で 6.6
時間。

## 結果

### 校正を替えた効果（`uniform4` どうし、3 seed）

差は「問題ごとに対を取った benchtrain − wikitext2」。`*` は 95% 区間が0を
またがないことを表す。層は (seed × タスク) の15。

| 指標 | wikitext2 校正 | benchtrain 校正 | 差 | 改善した層 |
|---|---|---|---|---|
| `acc` | 0.5799 | 0.6160 | **+0.0361** [+0.0311, +0.0409]* | 15/15 |
| `acc_norm` | 0.6146 | 0.6524 | **+0.0379** [+0.0329, +0.0427]* | 15/15 |
| `gold_nll` | 4.0079 | 3.6199 | **−0.3880** [−0.4106, −0.3660]* | 15/15 |
| `margin` | 0.5387 | 1.5063 | +0.9675 [+0.9333, +1.0028]* | 15/15 |
| `ref_kl` | 0.3288 | 0.2103 | **−0.1184** [−0.1264, −0.1104]* | 15/15 |
| `ref_agreement` | 0.8183 | 0.8535 | +0.0352 [+0.0299, +0.0405]* | 15/15 |

6指標すべてで区間が0をまたがず、15層すべてが同じ向きに動いた。

**大きさの見当。** 変換していない dense の `acc` は 0.6465 である。wikitext2
校正の 0.5799 は dense から 0.0666 低く、benchtrain 校正の 0.6160 は 0.0305 低い。
**dense との差の 54% が埋まった**ことになる。`gold_nll` では 40%、`ref_kl` では
36% である。

### タスクごとの正答率（3 seed 平均、wikitext2 → benchtrain、括弧は dense）

| タスク | `acc` | `acc_norm` |
|---|---|---|
| PIQA | 0.7356 → 0.7670（0.7802） | 0.7432 → 0.7769 |
| WinoGrande | 0.6406 → 0.6619（0.6953） | 0.6414 → 0.6627 |
| ARC-e | 0.6801 → 0.7226（0.7567） | 0.6392 → 0.6951 |
| ARC-c | 0.3478 → 0.3956（0.4292） | 0.3740 → 0.4133 |
| HellaSwag | 0.4955 → 0.5329（0.5708） | 0.6750 → 0.7141 |

5タスクすべてで上がった。校正に使った窓が1本しかない HellaSwag と ARC-c でも
上がっているので、「窓を多く割いたタスクだけが良くなった」わけではない。

### PPL（3 seed 平均、`uniform4`）

| 評価セット | wikitext2 校正 | benchtrain 校正 | NLL 差 |
|---|---|---|---|
| WikiText-2 | 6.9947 | 7.7160 | +0.0981 [+0.0939, +0.1027]* |
| C4-new | 10.2437 | 10.1573 | −0.0085 [−0.0114, −0.0054]* |

予想どおり WikiText-2 の PPL は明確に悪化した（6.99 → 7.72）。C4-new はわずか
に改善している。**PPL とベンチが逆を向く**ことが、この実験で最もはっきり出た
性質である。

### この校正の中では、配分の探索は効かない

benchtrain 校正の中で6構成を比べると、探索した配分は PPL では一様に勝つが、
ベンチでは勝たない（`uniform4` との差、3 seed）。

| 構成 | `acc` の差 | `gold_nll` の差 | WikiText-2 の NLL 差 |
|---|---|---|---|
| `uniform5` | +0.0023 | −0.0190* | +0.0109* |
| `uniform6` | +0.0011 | −0.0182* | +0.0168* |
| beam 幅1 | −0.0033 | −0.0010 | −0.0041* |
| beam 幅2 | −0.0022 | −0.0007 | −0.0003 |
| beam 幅3 | −0.0025 | −0.0067 | −0.0029* |

配分を替えて動く幅は ±0.003 で、校正を替えて動いた +0.036 の 10 分の1 以下で
ある。ベンチで見るかぎり、**どこに shared を置くかより、何で校正するかの方が
一桁効く**。

### 探索の健全性

| seed | 幅1 | 幅2 | 幅3 | 校正で選ばれた一様 |
|---|---|---|---|---|
| 0 | 0.12297（平均 x=4.38） | 0.11948（4.28） | 0.11886（4.22） | `uniform5` |
| 1 | 0.12541（3.97） | 0.12011（4.03） | 0.12091（4.00） | `uniform5` |
| 2 | 0.12679（3.88） | 0.12590（3.84） | 0.12340（3.91） | `uniform4` |

勝った配分を頭から測り直した差は9本すべて 0、非決定性の床も 0 だった。幅を
広げると良くなるのが6回中5回で、seed 1 の幅3 だけがわずかに悪化している
（ビーム探索は幅を広げても単調に良くなるとは限らない）。

**score は校正が違えば比べられない。** 上の値を report/04 の wikitext2 校正の
score（0.188 など）と並べても意味は無い。別のトークン上で測った KL である。

## 何が言えて、何が言えないか

**言える。** 校正データを測る対象に近づけると、5タスクすべて・3 seed すべてで
選択問題の成績が上がり、その代わり WikiText-2 の PPL が下がる。効果は
`acc` でも見えるほど大きい（report/07 で見えなかった配分の効果の7倍）。

**言えない（1）— どちらの経路で効いたか。** ここで比べたのは `uniform4` どうし
なので、配分は同一である。動いたのは分割と expert 重みを決めたトークンだけで
ある。ただし「どの層のどのニューロンが shared になったか」までは見ていない。

**言えない（2）— train split が eval split と同じ分布か。** ARC は難易度で
train/test が分けられている。それでも ARC-e で +0.0425、ARC-c で +0.0478 と、
5タスクの中でむしろ大きく上がった。

**言えない（3）— これが「ベンチマークに合わせ込んだ」ものかどうか。** 校正に
使ったのは train split だけで、採点される問題は1問も入っていない。とはいえ
「評価と同じ形式のテキストで校正した」ことは事実で、汎用の圧縮手法としての
数字と、この設定での数字は別物として扱う必要がある。C4-new の PPL がわずかに
改善している（悪化していない）ことは、単なる過適合ではない可能性を示すが、
1つの評価セットの 0.008 では根拠として弱い。

## 結論

校正データを何にするかは、この手法で**いま分かっている中で最も効く一手**で
ある。配分の探索（report/03〜08 で追ってきたもの）が動かす幅の10倍以上を、
校正セットの差し替えだけで動かした。

次は、今回入れなかった「答え部分だけを見る」を足す番である。今回は素のテキスト
として近づけただけで、採点オラクルは校正トークン全位置・全語彙の KL を見ている。
KL を取る位置を続きのトークンに絞る、あるいは選択肢の上の分布の KL に替えると、
測る対象にさらに近づく。ただし信号が痩せるので、非決定性の床を超えるかを先に
確かめる必要がある。
