# 01 SA配分キャリブレーション量：seed を変えたときのばらつき

2026-08-18 / 実験 `experiments/03_calib_seed_variance/`

### 目的

**キャリブレーションデータ8本という量が、配分探索を安定させるのに足りているか**を見極める。

## 実験設定

### seed が影響しうる箇所

| # | どこ | 扱い |
|---|---|---|
| ① | **配分を探すとき**の観察用文章（訓練用から8本） | **ここのシードを5種類試す** |
| ② | **モデルを組むとき**の観察用文章（訓練用から8本） | 固定 |
| ③ | ルーターの調整・診断用の文章 | 非使用 |
| ④ | 点数を測る文章 | 固定 |
| ⑤ | 統計の信頼区間を計算する乱数 | 20260813 に固定 |

### 手順

```
seed s（0〜4）→ 8本の文章を引く → beam search で配分を探す → 配分ベクトル v_s
                                                                    ↓
                          [②は seed 0 に固定してモデルを組む] → PPL を測る
```

対照として、全層を x=3 に固定した `uniform3` を同条件で1回測った（①を通らないので単一値）。

### 固定した条件

| 項目 | 値 |
|---|---|
| モデル | `meta-llama/Llama-2-7b-hf` |
| expert 数 N | 8 |
| 1トークンあたりに走る expert 数 A | 6（全構成で同一。**計算量は配分によらず一定**） |
| キャリブレーション本数 | 8本 × 2048トークン |
| キャリブレーション元 | WikiText-2 訓練split |
| 探索アルゴリズム | beam search、幅2 |
| 採点オラクル | `suffix_kl`（残りの層を未変換のまま走らせ、出力分布の KL を測る） |
| ルーター方式 | 現行 CMoE |
| 変換用 carve seed（②） | 0 |
| k_act / bias_speed | 10 / 0.001 |
| ブートストラップ | 10,000回、seed 20260813 |

### 評価データ

| データセット | 内容 | トークン数 | SHA-256（先頭12桁） |
|---|---|---|---|
| wikitext2 | WikiText-2 テストsplit 全体 | 341,469 | `add5c2673056` |
| c4-new | C4 validation 先頭1100文書 | 524,288 | `bbd0f3f758ec` |

**切り分けに使う文章（訓練split）と点数を測る文章（テスト/validation split）は完全に別**である。
評価用の文章はどの seed でも同一で、上記ハッシュで一致を確認している。

```bash
uv run python experiments/03_calib_seed_variance/run.py --oracle suffix_kl --seeds 0,1,2,3,4
```

全 seed で探索コスト（7,168 layer_forwards）と候補評価回数（441回）が完全に一致した。

**計算の再現性**：全 seed で、勝った配分を頭から測り直した結果が探索中の値と**差 0.000e+00** で一致した。
また同じ未変換モデルを2回読み出して比べた KL（機械の非決定性の下限）も全 seed で **0.000e+00** だった。
すなわち**測定ノイズは存在せず、観測されたばらつきはすべて①の引き直しに由来する**。

  計算結果には影響せず、保存済みデータから集計をやり直して同じ出力を得た

## 保存されているもの

再計算なしで後から利用できる形で、以下が残っている。

- 各 seed の `search_seed*/search.json` — 全層 × 全親 × 全候補（x=0〜6）のスコア、
  落選候補も含む枝の系譜、引いた文章の開始位置とハッシュ、全引数
- `eval/summary.json` — 構成ごと・データセットごとの**塊単位の平均 NLL を全件**
  （wikitext2 は166個、c4-new は256個）、PPL、変換情報、所要時間、全引数
- `eval/run.txt` — 画面出力の全体
- `variance.md` — 上記のばらつきの表

塊単位の NLL が全件残っているため、**集計方法の変更（別の統計手法への差し替えなど）は
GPU を使わずに再計算できる**。

## 結論

- seed（引く8本）だけを変えて配分探索を5回行い、**5回とも異なる配分ベクトル**が出た
- その PPL の標準偏差は **wikitext2 で 0.025524、c4-new で 0.032590** だった
- 対照 `uniform3` との差は、wikitext2 では5本すべてで改善側（-0.0073〜-0.0168）、
  c4-new では5本中2本が改善側・3本が悪化側だった
- 探索コスト・再現性（差 0）・所要時間は全 seed で一致しており、実行系は安定していた
